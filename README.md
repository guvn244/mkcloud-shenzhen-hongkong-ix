## 深港 IX VPS 是什么？和 IEPL、IPLC 专线差在哪

IX（Internet Exchange Point）是多个网络在同一个物理位置的流量交换中心。MKCloud 的深港 IX 产品从云厂内网接入深圳入口，从香港 BGP 出口向外访问，官方给的端内延迟参考是 1~2ms。每台 VPS 分配 1 个独立入口 IP 加 1 个独立出口 IP，你连入口、程序跑在 VPS 里，流量自动从香港出口发出去。

它和传统 IEPL/IPLC 专线的核心区别在接入方式。IEPL/IPLC 直连款绑定一个省份，家宽、办公室宽带可以直连入口；深港 IX 不限连入省份，但只接受特定云厂的内网网络连入——换句话说，没有前置云机，这条线你根本连不上。

这个设计带来了两个实际后果。好处是入口没有公网路由，天然扫不到、打不着，公开资料里普遍把“不暴露公网 IP、降低被扫描和通报的风险”列为 IX 方案的主要优点。代价则是前置机成了你的责任：官方知识库明确写了，受限入口能控制接入范围，但不等于天然防 DDoS，前置机和 VPS 的安全要自己做，默认也没有 SLA 保证。

前置机本身是个持续成本，选型前值得想清楚两点：

- 轻量实例的带宽不保险。有博主在 2026 年初的实测文章里提到，性价比高的前置方案集中在阿里云、腾讯云轻量实例（标称 200M），但已有不少实例被限速到 20M 甚至 1M 的案例；火山云延迟表现更好，但没有轻量形态，按量计费流量约 0.8 元/GB，长期跑不便宜。该博主的实测环境用的是火山引擎 ECS（2 核 / 2000M 带宽，机器约 550 元/年，共享流量包约 437 元/T·年）。
- 你得自己完成前置到入口的内网对接。官方知识库里有《IX 专线怎么连》的前置接入指南，流程不算复杂，但要求你会在云控制台做内网互通配置。

反过来说，如果你的业务本来就在腾讯云或百度云上，前置机是现成的，深港 IX 的接入成本几乎为零——这类用户就是它的目标客户。
